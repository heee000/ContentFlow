# ContentFlow 全项目再审：执行权修复后的剩余风险

日期：2026-09-24。审计源码：`fe6d0e314be5f1edbcb840e226cadd58bafa1a3d`，分支 `codex/enterprise-media-runtime`。

## 1. 结论与范围

**已经有真实产品的工程基础，但还不能作为稳定、完整、可靠的交付版本。** 当前优先项不是继续堆页面或换更贵的模型，而是消除执行与恢复冲突、保存已完成成果、限制资源消耗，并让内容、素材、指标和部署状态可信。

本轮没有确认匿名接管、远程代码执行或跨陌生租户读写的 P0；这不是排除了这些风险，也不是完整渗透测试。下文 P1/P2 是整改优先级，不是 CVSS。问题编号沿用历史登记；编号到 A51 不等于尚有 51 个安全漏洞。

本轮只审查、隔离验证和记录，不修改业务/测试代码，不提交、推送、触发 CI 或部署；不连接真实业务库，不调用真实模型、Embedding、媒体或社媒，不改变网络、代理、账户或密钥。原有受保护知识文件保持未读取、未哈希、未修改、未暂存。初始工作区除该文件外无未提交修改。

### 当前已经做了什么，不能重复算作缺失

- A37/A08 会话与工作区上下文隔离、跨页续期已有实现与前批 CI 记录；审核版本、未保存审批、渠道安全和最终发布确认也已有工程保护。
- A05/A45 生成接受幂等、A44/A48 事务原子性、A49 发布回执恢复、A50 UTC 响应已经进入本次源码，不能沿用旧报告中的“完全未做”或旧失败次数。
- A07 已有领取令牌、逐调用检查、业务事务写入保护及迟到调用证据。但本轮新增 A51，说明“能阻止过期 Worker”不等于“合法 Worker 的长任务也能正常完成”。
- 上一实施阶段记录的完整后端是 847 passed / 50 skipped，Edge 43 passed、模块/SSR 40 passed；这是已有阶段记录，**不是本轮重跑的完整结果**。本轮未验证 Ubuntu 在线版本，历史实机 `1502460` 不能当作当前在线事实。
- 同版本真实 PostgreSQL/MinIO、CI、迁移部署、真实平台验收仍未签收；历史绿色不能覆盖当前改动。

## 3. 必须优先处理的六类问题

### P1 / A51：业务写锁与心跳续租相互阻塞，慢存储不能可靠完成

证据：`contentflow/execution_fence.py:75`、`contentflow/storage_ledger.py:301`、`contentflow/storage_ledger.py:314`、`contentflow/job_queue.py:225`、`contentflow/worker.py:870`。

存储配额预留/flush 会在业务事务内获取 Job 写锁，随后仍在该事务中执行对象存储 put；心跳的独立事务也要更新同一 Job。存储调用拖长后，续租无法及时完成，合法 Worker 会自行过期。返回后旧执行被正确拒绝，但素材无法入库；补偿删除同样可能因失权被拒绝，留下无账本对象。

本轮先以自定义存储 handler 定位，再以实际 `asset.generate` 复现，并用相同耗时发生在存储事务前的成功对照确认。没有第二个 Worker 抢任务，没有人工撤销，也没有假造 heartbeat lost。3/4 秒是缩短时间的故障条件，**不是声称默认 300 秒配置已经在真实主机失效**。SQLite 有数据库级写锁；PostgreSQL 上同 Job 行锁的冲突是代码确认的风险，仍需真实行锁与 S3 慢响应验证。

关闭条件：重新划分短事务、外部 I/O、预留状态与最终提交边界；保证合法长操作可续租，失权者仍不能提交，并有可追踪的对象补偿/孤儿恢复。添加实际 PG/S3 下慢上传、锁等待、失权和断电恢复的正负用例。不能只延长租约或取消失权检查。现有执行契约中“不跨远端调用持有 Job 锁”的目标尚未在该存储路径兑现。

### P1 / A12：费用与资源没有硬上限

证据：`contentflow/providers.py:440/475`、`contentflow/knowledge_service.py:80`、`contentflow/schemas.py:250/269`。

已有调用账本、存储配额、登录限流和一次改写上限；但文本请求未设置输出 token 硬上限，响应整体读取，知识分块一次提交，若干 Brief 列表没有条目数/元素长度上限。仍缺每用户/工作区的生成并发、队列积压、日预算和未知结果费用预留。

后果：合法用户误操作或恶意滥用都可能耗尽费用、内存和 Worker。幂等只防同一次操作重复接受，不能阻止大量不同操作。先做输入/输出/批量/响应字节限制，再做预算预留-结算-未知冻结和并发/队列额度；不要用事后 token 统计冒充额度控制。

### P1 / A47：多平台部分成功的成果没有持久保存

证据：`contentflow/workflow_service.py:192/207/210`。

结果先保留在内存，所有平台完成后才创建内容；后一平台失败会让前面已经生成并审核的稿件无从继续编辑。调用 hash 和用量证据仍在，不等于可恢复的稿件。

关闭条件：每阶段/平台的版本绑定检查点、部分成功状态、保留待编辑成果、只续作缺失步骤。未知供应商结果仍需核对，不能借“续作”自动重新付费执行。

### P1 / A39：AI 素材就绪不保证是真正可用的图片/视频

证据：`contentflow/media_providers.py:871`、`contentflow/worker.py:870/964`。

AI 生成/下载链路主要相信标签、base64 与字节大小，没有统一使用实际解码门禁。人工上传和图库下载已有更强校验，不能把这些入口的能力视为覆盖 AI 生成。

关闭条件：各入口共享实际类型/解码、尺寸/像素、文件大小和视频可用性检查；不合格素材不可 ready/可发布。不要关闭安全预览去兼容坏素材。

### P1 / A40：审核范围小于实际发布内容

证据：`contentflow/review.py:34`、`contentflow/review_evidence.py:122`。

规则只看标题/正文，hashtags、CTA、平台布局/脚本等字段与最终发送物没有统一校验；版本绑定正确也不能弥补审核字段遗漏。

关闭条件：先定义各平台最终发布字段/渲染物，再以同一规范进行审核和预览；危险字段硬阻断与有理由的人工例外分开。不应只修 RuleReviewer 却保留调用方只传标题正文。

### P1 / A41、A24：部署就绪与版本交付门禁不可信

证据：`contentflow/api.py:284`、`contentflow/worker.py:2475`。

readiness 只验证 SELECT 1 和存储连通；缺表/错迁移仍可能显示 ready。Worker 生产入口还执行 create_schema，ORM 建表不能替代 Alembic、pgvector、约束和索引迁移。

关闭条件：独立迁移，API/Worker 检查支持的 schema/迁移版本，拒绝旧新 Worker 混跑；以同一源码、镜像、Web、配置和迁移版本完成服务验收及可回退交付。当前有令牌/回执等协议变化，不能直接覆盖老电脑上线。

## 5. 页面与可维护性

采用 web-design-guidelines 技能，获取 [当前 Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)，仅将导航状态、表单保护及大列表原则用于源码检查；本轮未执行浏览器交互、读屏、键盘或移动端完整验收。

- `web/app/contentflow-app.tsx:1309`：首次加载最多 22 类接口放在同一 Promise.all。指标已单独降级，其余模块失败仍可能阻止整个数据批次更新。按当前页/权限加载，模块独立错误、重试和取消。
- `web/lib/contentflow-api.ts:48`、`web/app/contentflow-app.tsx:1611`：最多加载 2000 条，再在本地筛项目。已显示截断提示，但本地筛选找不回未加载的老项目；提示“使用筛选”不等于提供了服务端定位能力。应做服务端过滤/分页与真实总数。
- `web/app/contentflow-app.tsx:1239`：页面、项目和选稿主要是内存状态，缺少可分享/恢复定位的 URL 与前进后退协议。

- `web/lib/contentflow-api.ts:24`：通用 API 请求没有统一的业务截止/取消协议；生成/发布接受已专门处理，不能将其覆盖范围推及全部请求。读请求重试与写请求结果未知须区别处理。

- 长交接文档含历史默认值与旧 HEAD/迁移描述。需要唯一当前发布清单（source/schema/image/Prompt/部署/验证状态），历史日志保留但不能和现行启动说明混用。本次索引只修正审计断点，不伪造部署签收。

## 6. 公共测试/企业交付还缺什么

这些是成熟度缺口，不全是已证实可利用漏洞；是否需要 SSO、RLS 等应由实际威胁模型与客户要求决定，不为小范围测试引入不必要复杂度。

- **安全边界**：现有 RBAC/工作区过滤之外，补完整租户/角色负向矩阵、反滥用额度、上传与出网边界验证。部署模板没有分开迁移与业务数据库身份，需最小权限与职责分离；本轮没有查询实机数据库角色。
- **身份与秘密**：账户恢复/MFA、设备与会话撤销、密钥轮换/旧密钥失效验证、历史日志和凭据暴露影响核查。真实轮换与权限调整另行授权，不因为本次审计自动执行。
- **数据治理**：知识撤回、删除/导出、保留期限、衍生索引/稿件失效及备份传播，避免原知识删除但旧内容仍无提示引用。
- **运维闭环**：DB+向量+对象在异机联合恢复；定义 RPO/RTO；告警实际到人、处置演练和恢复责任。`deploy/observability/README.md:50` 明确未内置 receiver，不能把有监控规则当作通知已完成，实机是否另配未检查。
- **容量与稳定性**：在 2 核 4G 目标机验证排队、并发、长事务、磁盘满、断网/断电、重启与持续运行；单次真实生成成功和本地测试总数不能推导承载量。
- **一致交付**：当前 SHA 的 PG/MinIO、浏览器、恢复、迁移与发布说明一体签收。在线 Python 漏洞查询授权仍未明确，本轮不重问或绕过；也没有重跑其他在线依赖扫描。

## 7. 建议推进顺序与开放门槛

1. **先收尾当前候选**：A51 长事务/存储/心跳；A41 schema 就绪；同版 PG/MinIO/迁移验证。不要在尚未签收的新基础上叠加发布功能。
2. **保护费用和成果**：A12 输入输出/额度/预算，A47 检查点，A09 配置快照和 A14 未知处置语义。
3. **保证产物与数据可信**：A39/A40、A35/RAG、A28/A13、A33；补多行业与人工质量验收。
4. **完成真实使用闭环**：A16 同步、服务端查询/深链接/草稿；异机恢复、通知和目标机容量。
5. **最后受控实测交付**：另行限定真实账号、调用预算与停止点；人工审核之前不自动生成正式素材或发布，不复用旧一次性授权。

| 阶段 | 当前判断 |
| --- | --- |
| 本人私有测试 | 可以继续受控体验已知版本，人工看护、避免无人值守批量；当前候选先过上述门槛 |
