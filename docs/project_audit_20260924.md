## 1. 结论

ContentFlow 已经有产品工程基础，不应再概括成只有页面的 Demo；但“可以跑通一次”与“可靠地反复运行、处理异常并对结果负责”之间仍有明显距离。

本次没有确认匿名接管、远程代码执行等 P0，不代表已排除。下文 P1/P2 是项目整改优先级，不是 CVSS。保留历史编号，不将 A01–A43 误称为 43 个仍未修复的安全漏洞。

## 3. 应优先关闭的风险

### A37 / P1：页面所处工作区与请求实际写入工作区可能不同

证据：`web/lib/contentflow-api.ts:97`、`contentflow/dependencies.py:69`、`contentflow/routers/auth.py:787`、`web/app/contentflow-app.tsx:1241`。

本次探针先保留 A 工作区页面语义，再通过共享 Cookie 切到 B，提交原页面的创建活动请求：返回 201，实际写入 B。属于同一用户已授权工作区间的错投，不是陌生租户越权；真实双标签页交互尚未验收。

整改：写操作携带页面预期的身份/工作区上下文，服务端只用于一致性校验，不替代鉴权；切区/退出跨页广播；取消或隔离旧响应。验收必须覆盖双页、慢响应、后台恢复、切换账号和未保存输入。

### A05 / P1：生成操作不能可靠去重

证据：`contentflow/routers/runs.py:91`，队列幂等键在第 161 行由新 run ID 生成。

同一 `Idempotency-Key` 两次提交返回 202/202，run ID 不同。队列内部去重不是用户操作去重，发布入口已实现的保护也不会自动覆盖生成入口。超时重试或重复提交可能增加稿件与费用；本次没有真实扣费。

整改：工作区内操作编号、请求摘要、唯一约束、同请求回执重放；不同请求复用编号拒绝，明确“重新生成”才创建新意图。需 PG 并发及回执丢失浏览器测试。

### A07 / P1：Worker 丢失租约后的逐调用保护仍不完整

证据：`contentflow/worker.py:2141` 在整个 handler 返回后检查 `heartbeat.lost`；`contentflow/provider_invocations.py:38` 的上下文不含 worker/attempt 执行代次。

已有续租和最终提交所有权检查，但不能据此保证旧进程在恢复运行后不会继续下一次计费调用。此项为源码确认，未做真实供应商或网络分区实验。

整改：外部调用前及领域写回校验执行代次；失去租约停止后续调用；已经送出的请求仍保留未知结果，不能承诺取消已送达的供应商请求。需暂停进程、租约回收、旧进程恢复的可控故障验收。

### A12 / P1：资源和费用没有端到端硬上限

证据：`contentflow/providers.py:438` 附近的请求体缺少输出 token 限额，第 473 行整体读取响应；`contentflow/schemas.py:236` 的部分数组没有长度上限；`contentflow/knowledge_service.py:83` 一次提交全部分块。

已有调用账本、超时和素材/存储配额，不等于文本生成预算、响应字节限制或工作区排队配额。异常供应商响应、大输入和大量重复任务仍会消耗资源。

整改：有界输入/响应/批次、输出 token 与总时长、每工作区并发和积压上限，预算预留/结算/未知费用保留。先做私测硬上限，不必先开发收费系统。

### A42 / P1：非有限指标可入库并持续破坏指标接口【本次新增】

证据：`contentflow/schemas.py:580`、`contentflow/routers/metrics.py:23/59`。`float` 字段仅限制非负，没有拒绝正无穷。

最小复现：有编辑权限的合成用户向自己工作区一个已发布任务录入 `impressions: "Infinity"`，POST 返回 **201**；之后 GET `/api/v1/metrics/summary` 返回 **500 / internal_error**。序列化异常为 `Out of range float values are not JSON compliant: inf`。没有攻击真实数据。

这不是仅发生于“取消任务”的边界。一个异常快照就能污染正常已发布作品的汇总；`web/app/contentflow-app.tsx:1267/1408` 把该接口放在整批 `Promise.all`，源码上会将指标错误扩大为页面整批加载/轮询失败。接口故障已复现，完整页面影响尚未独立浏览器验收。前提是编辑或更高权限，不是匿名全站攻击。

整改：API 与采集适配器统一有限数值、合理范围及计数语义，数据库增加相应约束；历史异常有审计地隔离/更正，不静默改成 0；指标面板失败不阻断其他业务。需 NaN/Infinity/溢出/异常旧数据、PG 与页面降级回归。

### A41 / P1（发布验收）：空数据库仍可被报为 ready

证据：`contentflow/api.py:282`。临时替换为没有任何表的内存数据库，`/health/ready` 返回 **200 / ready**。检查只执行 `SELECT 1` 和存储检查，不能发现缺迁移或错误 schema。

整改：就绪或启动门禁校验受支持迁移状态及必需 schema；API/Worker/迁移协调升级。不要把健康检查变成定时付费模型调用，也不要混同 Worker 心跳和业务验收。

### A08 / P2：多页正常刷新可能被当成令牌重放

证据：`contentflow/routers/auth.py:495`、`web/lib/contentflow-api.ts:34`。同一旧 Cookie 两次刷新为 **200、401**，随后会话查询 **401**。前端仅单页面合并刷新。

整改：跨页协调与严格受限的恢复协议，保留重放防护，不能直接取消安全检测。与 A37 一起验收；会话失效时保留编辑内容也必须覆盖。

### A09 / P2：排队配置和评测身份尚不能完整复现

证据：`contentflow/workflow_service.py:78`、`contentflow/prompt_eval.py:203`。

Brief/风格已有快照，但执行时重新选择当前 Prompt/Provider；Eval 通过门禁绑定模型名等信息，未绑定 endpoint 和完整参数指纹。同名模型换端点不应自动继承相同质量证据。

整改：冻结不含秘密的 Prompt、模型/端点/参数、索引身份；定义撤销与配置变更失效规则。实际 API Key 不应进入业务快照。

## 5. 体验、维护和测试疏漏

### A15 补充：当前浏览器验收存在时间相关的不稳定选择器

本轮第 10 条测试在进入审核页前超时。保存的页面快照显示按钮名为 `2 审核内容 11`，而 `web/tests/browser/review.spec.ts:18` 精确匹配 `2 审核内容`；生产组件 `web/app/contentflow-app.tsx:1621` 将待审数量渲染到按钮中。初始数据加载前后可访问名称不同，解释了此前通过而本次失败。

这是测试定位缺陷，不证明“远端改稿保护”本身失效；同样不能把未执行的 7 条测试写成通过。应使用稳定的语义名称或明确处理计数，并保留原业务断言；审计轮未直接修测试，也未通过重复重跑刷绿。

### A43 / P2：测试隔离晚于模块初始化【本次新增，源码确认】

`settings.py:18` 默认 `env_file=".env"`；`get_settings()` 还会创建本地存储目录。`db.py:49` 导入即调用 `build_engine()`，`api.py` 末尾导入即 `create_app()`。`tests/test_worker_v2.py` 在构造 `_env_file=None` 的夹具前已导入这些模块；浏览器启动脚本 `web/scripts/e2e-service.mjs` 虽过滤环境变量，API 的 CWD 仍是项目根目录，不能阻止 dotenv 读取。

影响：测试可能受本机密钥/生产配置和目录权限影响；仅在 fixture 中切换临时数据库不构成完整隔离。创建 engine 本身不是证明已连接或改写真实数据库，本次没有这类证据，也没有读取 `.env` 内容来排查。

整改：生产显式工厂初始化；测试在应用/DB 模块导入前配置独立 CWD、Settings 和环境，禁止真实出口；用合成“诱饵配置”证明不会读取或触碰生产目标。该项也修正此前审计“完全不读取本地配置”的过强措辞。

### A16/A17：页面数据耦合和工作状态恢复

- `contentflow-app.tsx` 为 **6,038 行**，最多 22 类加载一起成功才更新界面；按页加载、服务端过滤和独立错误区应优先于外观拆分。
