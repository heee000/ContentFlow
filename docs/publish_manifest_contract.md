# 最终发布物绑定 v1

2026-09-23，A25 的服务端一致性边界。不是数据库管理员不可篡改的数字签名，也尚未替代前端最终确认预览。

## 解决的问题

旧发布任务只记录正文版本。Editor 排期后换选封面，不会增加正文版本，Worker 会读到新封面并发布。现在创建任务时把当前正文、选用素材和渠道配置绑定到 `request_json.release_manifest`；执行、安全重试与脚本回退必须匹配这份记录。

记录包含契约版本、内容 ID/版本及正文摘要、渠道 ID/配置摘要、确定性排序的素材 ID/URI/SHA-256/大小/类型/来源及元数据摘要。渠道凭据密文仅参与摘要计算，不复制密文或明文到记录、响应或日志。连接测试的状态变化不改变发布物；账号凭据轮换或配置改变则需要新确认。

## 行为与边界

- 所有选用素材必须 ready、有工作区内的存储 URI、大小和 SHA-256 才能排期。未准备完毕应返回素材步骤，不再先排入必然失败的任务。
- 创建记录、执行前核对时按内容→渠道→素材的顺序持锁；已有任务先锁自身 PublishJob，不倒过来锁素材→内容。等待锁后重读，防止使用 ORM 旧缓存。
- 官方分发在同一事务中完成检查并登记开始，提交后才调用平台。传给适配器的是脱离 Session 的内容/素材/渠道副本，后续编辑或 ORM 过期不会把新的字段偷换进去。已经开始的分发以该次固定副本为准，不声称改稿能撤回已发出的请求。
- 素材在适配器实际读取时核对大小和 SHA-256，不接受记录之外的 URI。检查使用的就是最终发送/导出的字节，不做“先校验一次、之后不受控重读”。官方 API、导出和脚本包共用此层。
- 任务创建后换图/改稿/修改发布配置：待执行的旧任务会拒绝，需重新确认并创建新任务。安全重试与脚本回退不能借机重新拍摄一份不同发布物。切换为脚本本身沿用已有审核者授权及审计，不改已绑定的正文/素材/渠道摘要。
- 没有 manifest 的旧待执行任务不自动补造确认；已提交、已完成、草稿已创建等领域终态仍优先返回，避免因为升级再次调用平台。既有结果不确定/人工对账语义保留。
- SHA-256 校验失败只阻止错误文件发送，不保证所有适配器都能证明“未产生副作用”。微信封面读取在平台写入前，因此沿用 read_assets 安全失败；其他不确定情况仍保守核对，不盲目重试。
- 脚本包生成沿用既有事务与存储补偿；本次不宣称消除了所有存储 I/O 持锁时间或实现了外部对象版本保留。

## 验收与尚未完成

隔离测试覆盖排期后更换不同文件的封面、正文/配置/校验和漂移、安全重试与脚本回退、旧任务拒绝/终态重放、提交后并发修改及 Session 过期、素材真实字节校验。微信 MockTransport 仅允许 token GET，校验失败没有任何平台 POST。另有 PostgreSQL 排期/选图竞争测试；实际结果以实施进度页及确切提交 CI 为准，不将本地跳过计为通过。

**A25 尚未全部关闭**：下一步前端要显示最终正文、主封面及渠道行为，预览返回指纹，确认提交携带该指纹；服务器拒绝预览到确认之间的变化。本版仅冻结创建任务时的服务端状态，不能证明用户看见过并确认了同一份预览。浏览器旅程、用户验收和部署仍待完成；不因此声称已解决 A04 未保存审批或 A06 审核版本问题。
