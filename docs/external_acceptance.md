## 2026-08-09 微信公众号受控写入

- 授权范围：用户明确允许创建测试永久素材和草稿，且暂不公开发布。
- 前置检查：白名单调整后，Access Token、素材计数和草稿计数均成功。
- 写入路径：通过真实 `WechatConnector.publish`，使用内存生成的测试 PNG，渠道配置强制 `auto_publish=false`。
- 可观察结果：图片素材增加 1，草稿增加 1，连接器状态为 `draft_created`。
- 安全断言：调用跟踪确认没有请求公开发布提交端点；没有输出或写入任何凭据。
- 外部副作用：该永久图片素材与草稿当前保留在用户公众号后台。后续如需清理，应由有权限的管理员在平台后台核对标记后删除，不能在未确认目标的情况下批量删除。

## 2026-08-23 本地模型、媒体策略与白名单复验

- 微信公众号：白名单更新后无副作用鉴权取得 7200 秒令牌；2026-08-24 凭据在隔离生产栈内加密保存并由 Worker 测试为 `connected`，`auto_publish=false`；未创建新素材、草稿或公开发布。
- 文本模型：先用实际 JSON response_format/temperature 参数完成小额预检；随后在隔离生产栈执行三阶段 Eval、双人治理和知识检索后的公众号工作流，Eval passed、Prompt active、生成结果停在人工审核。该证据仍不替代限流、超时、费用与质量漂移矩阵。
- Embedding：从 BGE-M3 官方固定提交下载并在本机 CPU 执行单条/批量中文向量化；Linux Worker 镜像以非 root、完全禁网、offline cache 推理成功。真实测试副本在 PostgreSQL/pgvector 中索引为 4 个知识块并参与内容生成。
- 媒体：用户选择人工上传真实封面，系统不再把缺少媒体 API 当作生成成功；本轮真实工作流已有 planned 任务等待审核，尚未收到用户实际封面文件，因此只签收状态机、类型/版本门禁和安全上传回归，不签收最终视觉质量或本轮微信草稿。

## 2026-08-24 公众号出口 IP 阻断与副作用边界

- 用户在工作台先后安排的 4 个公众号任务都在获取 Access Token 阶段返回 `40164 invalid ip`，数据库均无 external ID；调用尚未到永久素材、草稿或公开发布端点，因此本轮没有创建新永久素材、草稿或公开文章。
- 诊断时 Worker 容器没有显式代理环境变量，但宿主机出口受代理/网络路径影响发生变化；动态出口不能依赖一次白名单长期工作。用户计划关闭代理后重新测试渠道。
- 该旧任务由当时版本记录为结果不确定，继续保持人工对账语义，不追溯修改历史状态。新实现从本阶段起把 Token、素材检查和本地读取错误分类为外部写入前安全失败；鉴权失败会使渠道变为 `invalid`，只有复测恢复 `connected` 后才能由 reviewer 显式安全重试。
- 本节只签收错误位置与“无平台写入”证据，不签收代理关闭后的新出口、渠道恢复或新草稿。后续真实复测成功后再更新本表。
## 使用规则

1. 后续真实调用先更新本表的授权范围和预期副作用。
2. 每种能力分别记录成功、超时、限流、凭据过期、权限不足、平台拒绝和不确定结果；不能用单次成功替代异常矩阵。
3. 日志和文档只保存摘要、计数变化、平台错误码类别和追踪哈希，不保存秘密值或完整内容。
4. 公开发布、删除线上素材、改变账号配置等高风险动作必须再次取得明确授权。
5. 媒体 conformance 会产生真实图片/视频并可能计费；只有在目标 Base、Key、模型名和下载域名明确后运行。报告只保留脱敏指纹；自动通过不能替代账单核对、人工质量抽检和故障注入矩阵。
