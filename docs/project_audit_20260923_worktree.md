## 1. 结论

ContentFlow 已有真实工程基础，不能再称为只有界面的玩具 Demo；但当前还不是可无人看护运行、可公开接纳不可信用户的成熟产品。主要距离不在按钮数量，而在操作正确性、费用控制、内容质量和运行验收。

## 3. 新发现和当前必须先收尾的问题

### A36 / P1：文本模型请求可跨域、降级重定向并继续携带 API Key【离线适配器复现】

- 位置：`contentflow/providers.py:455` 使用默认 `urllib.request.urlopen`；`settings.py:550` 校验初始地址，生产要求 HTTPS，但没有约束后续跳转。应用没有自定义禁止重定向的 opener。
- 复现：真实 `OpenAICompatibleProvider.complete_json()`，仅以离线 transport 替代网络。首次 HTTPS 返回 302，目标为另一域名的 HTTP；标准重定向处理发起第二次请求，仍带同一虚构 Authorization，最后调用成功返回 JSON。
- 前提：已配置的模型服务/中转站返回这种跳转；不是匿名用户直接指定任意目标，也未发现真实密钥泄露。即便最初使用 HTTPS，也不能保证后续凭据传输仍安全。
- 整改：文本 API 默认禁止重定向；必要的规范化跳转只能显式验证同一 HTTPS Origin，严禁跨域或降级转发凭据。统一所有外部客户端的目标、跳转、超时、大小及日志边界，而非仅修社媒连接器。
- 关闭：301/302/303/307/308、跨域、降级、回环和凭据哨兵矩阵；断言网络跳转前拒绝，错误/日志不含 Key。本轮没有实际发包。

### A04/A06 / P1：审核前后端协议尚未闭合，存在阻断与旧稿审批两种问题【代码确认＋API 复现】

- `web/app/contentflow-app.tsx:2646` 审批只发保存版本；`:2766` 是独立、非受控编辑表单，没有 dirty 门禁。用户输入尚未保存时，审批不会提交当前输入。对拥有有效当前审核证据的保存版本，依然可能批准旧稿。
- 新后端 `routers/contents.py:261` 对缺失/旧版 AI 证据或规则失败要求明确确认及理由；前端 `:2658` 不发送 `acknowledge_review_warnings`，也没有确认入口。
- 探针：使用当前页面相同的审批请求，编辑后的内容返回 409；用户无法从现有页面完成要求的确认。全套的手动素材、来源矩阵和生成→编辑→审批旅程因此失败。
- 新响应已标记 AI 证据 current/stale/unversioned，但页面 `:2792` 仍直接展示旧分，缺分又转为 `0.0/10`，混淆“没有当前评审”与“质量零分”。
- 相同正文再次保存仍升版、使审核失效并重建素材计划：探针内容未变但版本变为 2。这不是实际改稿，应明确无变化时不产生新版本。
- 整改：保存成功的返回版本立即成为审批基线；脏稿/保存失败/并发冲突时不能审批；切稿、切项目/工作区、离页有保护；所有互斥操作统一 busy。准确展示过期证据，提供显式人工例外流程，不自动收费复评。
- 关闭：不能仅更新测试让其变绿；还要真实浏览器覆盖编辑未保存、保存失败、远端改稿、历史稿件升级、确认理由和导航保护。

### A38 / P2：旧稿件首次人工审核会覆盖未归档的原 AI 证据【API 复现；在制代码】

- `review_evidence.py:63` 重建审核结果时不保留未绑定版本的旧模型内容；`routers/contents.py:278` 先替换 `review_json`，`:365` 再归档人工决定。
- 新生成内容有 generated 快照，编辑也有 superseded 快照；但升级前已有稿件没有这些新表记录，直接审批/驳回走到上述缺口。
- 探针：旧稿包含模型通过和 9 分，直接驳回返回 200，历史表只有 human_reject，原模型审核没有进入历史，当前记录也已被替换。
- 整改：转换旧证据前原样归档并标为未绑定版本；不能把旧证据伪装成当前版本证据。覆盖升级前稿件的批准、驳回及事务回滚。
- 这是当前未提交实现的迁移兼容缺陷，不能据此断言线上已经丢过证据。

### A37 / P1（多工作区使用前）：页面工作区与 Cookie 工作区可能不一致【协议复现＋页面源码确认】

- `routers/auth.py:787` 切换工作区会轮换共享 Cookie 所指向的会话；`web/lib/contentflow-api.ts:97` 请求随当前 Cookie 发送，没有绑定页面预期工作区。
- 页面只在初始化或本页主动切换时更新 session；没有跨标签页通知。后台加载/轮询的结果写回也缺少身份/工作区代次校验及旧请求取消，见 `contentflow-app.tsx:1223/1404/1486`。
- 协议探针：页面先持有工作区 A 上下文，另一操作将同一 Cookie 会话切到 B；原页面准备的创建活动请求返回 201，活动实际写入 B。
- 这是同一用户已获授权工作区之间的错投风险，不是绕过权限访问陌生租户。真实双标签页 UI 尚未测试；快速切换时旧请求覆盖页面数据为源码确认风险。
- 整改：写请求带页面预期 workspace/session context，服务端只用于一致性核验，不能信任它替代鉴权；不一致返回冲突。跨页广播切换/退出并清理身份缓存，旧请求不得写回新工作区视图。

### A34 / P2：非空 PATCH 契约修复只覆盖内容，活动仍返回 500【API 复现】

- 新 `ContentUpdate` 已拒绝显式 null，5 类字段回归通过；不能继续报告这些内容字段完全未修。
- `schemas.py:255` 的 `CampaignUpdate` 仍接受 `name=null`，`routers/campaigns.py:108` 直接赋值。隔离 API 返回 500。
- 需要统一省略/显式 null/空白/空集合/平台去重等语义，并为活动编辑定义并发更新策略。客户端非法输入应在落库前返回可解释的 4xx，不把数据库异常当校验。

### 内容质量与知识检索

1. **A10：召回不等于证据。** `knowledge_service.py:156` 附近没有最低相关性拒绝，`workflow_service.py:233` 保存全部召回 ID 为来源，不能证明具体句子被知识支持。需要“无资料也可诚实拒答”、主张级引用和冲突处理。
2. **A11：索引身份不完整。** 保存 embedding_model，但查询不按模型/版本过滤；同为 1024 维不等于同一向量空间。全文分块一次 encode_many，缺少有界批次及持久进度；上传大小上限不是供应商 token 或内存安全保证。
3. **A35：返回向量对应关系未严格校验。** `embeddings.py:240` 只排序并查数量/维度。当前 MockTransport 再次接受 `[0,0]`、`[-1,2]`，还接受布尔 index；应要求严格整数、唯一且完整覆盖输入，错误不落库。不据此推断真实索引已损坏。
4. **A28：跨行业仍被旧 Demo 规则污染。** `review.py:67` 在产品名缺失时补“使用某产品整理路线信息”；餐饮探针实际得到“使用合成餐馆整理路线信息”。`models.py:22/53` 还有地图 CTA 默认值。必须删除无依据能力补写，增加多行业回归。
5. **A13：质量评估过于依赖模型自评分。** `content_agent.py:104` 达目标分后，即使仍有具体修改指令也可能不改；应明确阻断问题和建议，建设真实任务集与人工盲评，以事实错误、改稿量、风格一致性、成本/时延判断质量，而非只提高 Agent 轮数。
6. **平台成品仍有限。** 公众号 `publication_payload.py:9` 为转义纯文本段落，尚非完整图文排版/正文插图系统；微信指标接口仍 NotImplemented，抖音自动对账未实现，小红书仍是人工/本机辅助。不能以三个平台选项表示三套完整自动运营。
7. **AI 素材内容校验需统一。** `worker.py:923` 附近主要使用 Provider 声明的 MIME 和受限字节入库 ready，没有复用人工/搜索图片的实际解码和规范化；视频也需容器、编码、时长等校验。没有进行恶意媒体攻击实验。
8. **A33：效果复盘口径不可信。** `routers/metrics.py:65` 起直接统计/求和全部快照。隔离复现同一作品累计曝光 100→150，summary 返回曝光 250、样本 2；还接受已取消发布任务的录入。应明确累计/增量口径、作品去重、时点和来源，处理重复、乱序与更正后再输出运营建议。

## 5. 扩大使用前的系统性缺口

- **数据生命周期（A18）**：知识更新、撤回、删除和索引联动不完整；活动归档不是租户删除。需定义对象、向量、审计和备份中的保留与删除边界，不能盲删历史证据。
- **身份与纵深隔离（A19/A20）**：已有工作区鉴权/RBAC和撤销会话，不应说毫无隔离。运行与迁移数据库权限拆分、跨租户负向矩阵、账号恢复、MFA、密钥轮换演练等仍不足；企业 SSO/RLS 按明确场景设计，不把缺 RLS 直接称为已发生越权。
- **网络出口（A21/A36）**：社媒 Origin 固定、媒体域名允许列表已存在，但所有外部客户端还没有统一的重定向/DNS地址/出口策略。文本跳转漏洞表明逐客户端修补尚未形成统一边界。
- **运行闭环（A22/A23）**：有备份/恢复脚本与 Prometheus 规则；`deploy/observability/README.md:50` 明确没有真实 receiver。当前目标主机异机恢复、实际告警到达、断电/磁盘满/容量/长稳仍缺本轮签收。Tailscale 不提供固定微信出口，也不消除老电脑单点故障。
- **发布与版本事实（A24）**：源码、未提交状态、数据库迁移、Prompt/模型、部署版本需一起记录；最新安全代码未获部署签收，不能凭历史 CI 宣称运行环境已修。API/Web/Worker/迁移必须协调升级和验证回滚兼容。
- **测试范围（A15）**：已经有 6 条真实发布页面旅程，不再是“没有 E2E”。但审批脏稿、旧稿升级、多标签页、工作区错投、未知结果恢复等还没有对应完整浏览器矩阵；绿单测没有覆盖跨层契约。
- **体验与可维护性（A16/A17）**：主界面超过 5,000 行，首次最多 22 类集合/控制面请求由 Promise.all 绑定，单项错误影响整批；大列表依赖前端全量加载/本地筛选，超过上限后的历史定位不完整。缺项目/稿件深链接、刷新恢复和草稿保护。已有加载反馈与项目标识，不应再只堆动效。

UI 源码参照 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 的未保存保护、导航状态和大列表要求；没有据此冒称完成键盘、窄屏或读屏实测。

## 7. 推荐路径与进入条件

1. **阻止泄露和错操作**：A36；收尾 A04/A06 的前后端/历史迁移及 A38；A37 与 A08 的工作区和多页会话一致性。恢复全套回归，补失败对应的真实浏览器测试，不能单纯放宽测试。
2. **控制重复执行与费用**：A05、A07、A09、A12、A14，先定义私测可承受的请求、任务、时长、预算和未知结果策略。
3. **把内容质量和复盘做实**：去 Demo 语义、修 Embedding 对应与索引身份、加相关性/事实引用、修累计指标口径、建立人工质量评测；再完善图文成品能力。
4. **私测运行签收**：候选版本协调升级、备份及异机恢复一次、告警实际送达、重启/故障与小主机容量。真实模型/封面/微信验收需要独立受控授权，不重复消费旧一次性授权。
