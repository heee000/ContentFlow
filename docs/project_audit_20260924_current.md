## 1. 结论

**有真实产品工程基础，可以继续受控私测，但尚未达到稳定、可靠、完整可交付的产品状态。** 最大差距不是页面数量，而是操作只执行一次、失去执行权后停止、费用可控、生成结果与统计可信，以及故障后能恢复。

本轮没有确认匿名接管、远程代码执行或跨陌生租户读写的 P0；不是已排除这些风险，也不是完整渗透测试。下文 P1/P2 表示本项目的整改优先级，不是 CVSS 分数。A01–A47 是历次问题编号，不能解释成当前仍有 47 个安全漏洞。

当前在制会话候选还有测试失败及真实 PostgreSQL 验收空缺，不应直接替换正在使用的版本。公网部署计划仍冻结；本轮没有检查 Ubuntu 在线状态。

## 3. 优先关闭的高影响问题

### A05 / P1：生成请求缺少业务级幂等

- 证据：`contentflow/routers/runs.py:91/145/161`；相同活动、请求体和 `Idempotency-Key` 两次返回 **202/202、不同 run ID**，本轮再次复现。
- 后果：网络重试、重复点击或回执丢失会创建不同生成任务；队列按 run ID 去重防不住这一层，真实配置下有重复费用风险。
- 关闭条件：工作区内操作 ID + 请求摘要 + 唯一约束；同意图重放原回执、异意图复用 ID 拒绝；覆盖 PG 并发、丢回执和主动重新生成。

### A07/A12 / P1：执行权和费用没有形成完整硬边界

- 证据：`worker.py:2155` 在 handler 返回后才检查失租；`provider_invocations.py:38` 上下文没有 Worker/attempt 代次。已有心跳和队列完成保护，不等于每次外部调用、领域写回都受到旧 Worker 隔离。
- 文本请求 `providers.py:438/473` 无输出 token 硬上限且整体读取响应；`knowledge_service.py:80` 一次提交全部分块；若干 Brief 数组没有条目数/元素长度上限。存储配额、认证限流和一次改写上限已存在，但不是工作区调用预算、排队及并发限额。
- 关闭条件：调用前/写回时校验执行代次；失租不发下一次调用；工作区输入、输出、并发、积压、费用预留/结算有硬上限。已发出的调用仍可能完成，保留未知结果核对，不能承诺通用 exactly-once。

### A47 / P1（恢复能力）：后一个平台失败，前面已生成的文案也没有持久保存【本轮新增】

- 证据：`workflow_service.py:193/194/211/310` 先将所有平台结果放进内存列表，全部完成后才建立内容及 run 结果。
- 通过真实 `Worker.run_once()`、临时数据库和实际 Mock 内容 Agent：第一平台公众号已返回非空文案，再受控令第二平台抛 TimeoutError。最终 **run=failed、保存内容 0 条、run.result_json 为空**。
- 这是受控故障注入，不是实际供应商故障或真实费用；生产调用账本可能仍有调用摘要，不应说所有调用证据都丢失。但可供用户继续编辑的已完成稿件没有保留下来。
- 关闭条件：按平台/阶段保存有版本与配置绑定的检查点；明确部分成功和待确认状态，只续作尚未完成部分，不能将不完整结果冒充整批成功，更不能自动重放结果未知的调用。

### A39/A40 / P1：素材 ready 和规则通过不代表最终发布物有效

- `media_providers.py:872` → `worker.py:864`：**12 字节 `not an image`** 经过真实解析与存储路径，被保存为 **ready / image/png**。人工上传已有独立格式校验，缺口是生成/下载链路没有统一实际解码门禁。
- `review.py:34` 仅检查标题/正文；禁用词放入 hashtag，本轮仍 **passed=true**。`review_evidence.py:122` 的重新审核也只传标题/正文；仅修改 RuleReviewer 而不修改调用字段并不能完整解决。
- 关闭条件：各素材入口共用实际类型、大小、尺寸/像素、视频格式等校验；规则校验覆盖真正发送/导出的字段及渲染结果。区分硬阻断与有理由的人工例外，不用 MIME 或模型分数替代验证。

### A41 / P1（交付门禁）：数据库可连接被误当成系统可用

- `api.py:283`：临时替换为没有任何表的数据库，`/health/ready` 仍 **200 / database=ok**；本轮再次复现。
- `worker.py:2445` 生产入口仍 `create_schema()`，与 `docs/operations.md:23` 的“生产不会自动 create_all”不一致。ORM 建表不能替代迁移、pgvector、索引和约束校验。
- 关闭条件：独立迁移，API/Worker 验证支持的迁移版本及必要 schema，错版/缺表不得就绪；轻量存活检查与业务就绪检查分开。

### A37/A08 / P1（在制验收）：会话防错投已实现，但不能提前关闭

当前已有 Cookie 上下文前置条件、请求/分页代次、跨页续期协调和保留输入。逐入口负向矩阵、四项 PG 并发代码、实际 TS 模块测试、单源兼容和升级契约也已补入工作树；不能再称为“完全没有保护”。

但候选有上述前端失败，PG 测试本机跳过，没有当前 SHA 的远程 CI。API 新要求 Cookie 上下文头，旧 Web 会收到 428，必须协调升级。多前端来源/浏览器 profile 不是同源 Web Locks 能解决的范围；见 `browser_session_contract.md`。

## 5. 内容产品本身还缺什么

1. **有来源不等于有依据（A10/A11）**：检索没有相关性拒绝、索引模型身份过滤；保存召回 chunk 列表不等于逐事实引用。需要主张-证据对应、来源版本、冲突处理、不相关时拒绝借用。
2. **内容质量没有业务验收基线（A13）**：目前改写主要由 passed/总分驱动，高分下的重要修改指令可能不处理。建立多行业任务集和人工盲评：事实错误、可直接使用率、人工修改量、平台适配、成本与时延；同模型自评不能代替它。
3. **残留业务硬编码（A28）**：通用产品漏提产品名时，规则修复仍补“使用…整理路线信息”，本轮复现。清理地图/城市等领域假设，不能凭空补产品用途；这与采用哪家模型无关。
4. **配置尚不能完整重现一次生成（A09）**：Brief/style 已快照，排队任务仍在执行时重新选择 active Prompt、模型/端点/参数。需要不含秘密的完整执行快照和 Eval 失效规则。
5. **公众号成品能力仍薄**：当前正文主要安全纯文本转段落；正文插图、富排版、图文对应、实际渲染验收不足。模型写出布局字段不等于渠道真的发布该布局。
6. **三平台不是同等完成**：公众号指标接口、抖音企业权限/对账、视频成片与兼容验收、小红书人工导出边界仍需分别签收。不能把共用流程跑通叫“三平台自动运营完成”。
7. **图片可搜索不等于可放心使用**：来源/许可/署名、适用场景、内容与封面一致性、替换后审核、失败退回人工的体验都需要产品验收，不只是让 URL 能下载。

- `web/app/contentflow-app.tsx:1303` 一批等待最多 22 类接口；指标已独立降级，但其他不相关接口失败仍会阻止整批更新。按当前页/权限加载、模块单独错误和重试。
- `web/lib/contentflow-api.ts:51` 最多 20×100 条后本地筛选；`contentflow-app.tsx:1605` 的项目筛选不能找出尚未加载的老记录。改成服务端筛选/分页，并显示真实范围。
- `contentflow-app.tsx:1234/1662` 的页面/项目主要在内存状态；没有明确的项目/稿件 URL、前进后退与恢复定位。审核离开保护已经有，但其他表单与持久草稿仍需补齐。
- `web/lib/browser-session.ts:207` 起普通业务 fetch 没有统一截止时间；认证请求的 20 秒超时不能代表业务请求都有超时。定义读请求取消/重试与写请求结果未知的不同处理，不能超时就自动重发写操作。
- 故障状态应明确“影响哪个项目、为什么、现在可做什么”；按角色简化高级控制。已有进度条/减少动画设置不等于完整易用性验收。
- 约六千行主页面和大量相互依赖状态增加回归成本；优先按业务状态和请求边界拆分，再拆视觉组件。保留端到端不变量，不以代码行数减少充当稳定性改进。
- 交接文档历史过长且包含过时默认值/启动方法。保留历史，同时维护唯一当前候选、源码/部署/schema/Prompt 版本和未过门禁入口；本文及进度末节先承担当前索引，不删除旧记录。
