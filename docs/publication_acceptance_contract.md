2026-09-24，A44/A48/A49/A50。与 [最终发布物绑定](publish_manifest_contract.md)、[生成意图](generation_intent_contract.md) 配套；当前实际验收、源码与部署状态以 [实施进度](IMPLEMENTATION_PROGRESS.md) 为准。

## 问题与改动

| 原问题 | 当前实现 | 仍不保证 |
| --- | --- | --- |
| SQLite 首次 SAVEPOINT 写导致接受审计失败后遗留孤立 PublishJob | `insert_on_unique_key` 使用 SQLite/PG 原生定向 `ON CONFLICT DO NOTHING RETURNING`；发布记录、队列和审计共用调用者事务 | 不改变供应商事务；PG 实际竞争需单独验收 |
| 队列冲突直接 rollback 整个 Session，撤销前序业务 | 队列只抑制指定幂等键冲突，核对工作区/类型/负载身份；不 commit/rollback 调用者；其他约束错误正常传播 | 不把同键不同负载或工作区当作成功，也不覆盖原任务时刻/尝试上限 |
| 回执损坏、读取失败被当作无请求 | `publication-intents.ts` 严格字段/类型/模式/时间校验，区分 absent/valid/invalid/unavailable | 浏览器 sessionStorage 不是跨设备持久工作台，也不能防用户自行删除存储 |
| 保存没有读回，清理不核对身份 | 发送前确认保存成功；重放只允许相同意图；清理只允许相同记录，已清除可幂等处理 | 不能保证供应商 exactly-once，不能超时后更换编号自动重发 |
| 旧组件迟到响应删除新记录 | Hook 使用同步在途门禁，清理再比较记录；请求采用 30 秒截止；失回执保留原意图 | 原请求可能已被服务器接受，客户端截止时间不取消服务器任务 |
| SQLite 返回 naive datetime 导致浏览器按本地时间解释 | 所有声明 datetime 的响应模型统一转为 UTC，JSON 带 Z；偏移输入保持同一时刻；不修改数据库或请求时间校验 | 不追溯修复人为写错的历史时间，也不解决日期输入的所有夏令时歧义 |

## 只读核对与人工处置

- 新增 `GET /api/v1/publishing/intents/{request_id}`，按当前登录工作区查原回执，不要求新预览，不入队、不补发。无记录返回 404；这仅表示此时尚未查到，**不是原请求永远不会接受的证明**。
- queued/scheduled 记录必须有身份匹配的 dispatch Job。旧孤立记录返回 `409 publish_receipt_incomplete`；不自动创建队列，不假定此前没有外部副作用。多个同编号历史记录同样拒绝自动恢复。
- `PublishJobResponse` 增加可空 `request_id`，任务列表展示任务 ID 和操作 ID。旧记录缺编号时保留 null，不伪造历史回执；不返回 preview token、完整 request_json 或平台凭据。
- 页面可“只读查询原任务”，也可“重试获取原任务”原样 POST；二者不等价：后者在从未接受时可能接受任务，前者绝不会创建。回执必须匹配操作、稿件和渠道身份，错误回执保留待核对状态。
- 损坏/拒读会阻止新发布，提供“重新读取回执”；没有自动删除坏记录、自动改编号或刷新后自动重发。
- 人工重新开始是显式风险处置，不是自动恢复：界面要求核对服务器列表和平台记录，并警告清除不会取消服务器任务、原请求可能仍处理中。不可读时不能清除；损坏记录只允许清除用户刚核对的同一原始快照，已变成新有效记录或其他快照时拒绝。
- `publish_receipt_incomplete` 和 `publish_intent_conflict` 不走普通 4xx 清理；已经待核对的请求遇到其他错误同样保留。新请求收到确定性拒绝时退出旧预览；服务器接受后页面刷新失败与“没有接受”分开表达。

## 时间边界

`UTCResponseModel` 在字段完成类型校验后规范化实际 datetime，`ORMModel` 继承该规则；非 ORM 的成员、审计、风格、供应商调用、Worker 健康和存储响应同样使用。可空时间保留 null，嵌套模型各自负责自己的时间字段，不重写任意用户 JSON 文本。

应用持久时间约定 UTC；SQLite 驱动丢失 tzinfo 时恢复 UTC，带偏移的 datetime 转 UTC。首次接受、精确重放、只读查询及列表应给出同一时刻。前端 datetime-local 在用户本地时区转换为 ISO 后发送，显示时再转本地时区，不对 API 字符串盲加固定 8 小时。

## 验收与升级

- 原子性：SQLite 入队/审计失败无孤立记录，孤立回执拒绝；受控查重 miss 后实际唯一冲突保留调用者更新；不同身份拒绝，非幂等约束不吞错，调用者 rollback 撤销新入队。
- PG：独立数据库中的入队/审计失败回滚和真正两会话争同键；同时核对回执时间与只读查找。没有专用 TEST_DATABASE_URL 时跳过，绝不算通过。
- 前端：16 项实际 TS 存储回归已接入 `npm test`，不是未接线的旁路测试；浏览器新增损坏恢复、拒读、静默丢写、错误回执、孤立/404 保留、同回执双组件到达和旧回执不删新记录。
- 时间：模型/实际 API 的首次/重放/列表；真实页面 UTC、上海、纽约冬季/夏季的本地输入→UTC 回执→本地显示。
- API/Web/Worker 必须按同一候选协调升级。A49 新 Web 需要响应里的操作编号与只读查询入口；旧 API 缺字段会保守保留回执，不冒认成功。A44/A48/A49/A50 不新增数据库迁移；本批包含既有 A05 迁移 d8e9f0a1b2c3，不能漏执行。
- 后续 A07 又增加 e9f0a1b2c3d4 执行令牌迁移；当前候选应迁移到此 head，并按 [执行权契约](worker_execution_contract.md) 停止旧 Worker、协调升级，不能停在本契约对应的旧 d8 head。
- 没有在本轮修改真实库、自动补发旧任务、触发真实模型/媒体/平台或部署。剩余失租执行权、预算、阶段检查点、媒体字节/最终字段、就绪门禁仍是独立开放项。
