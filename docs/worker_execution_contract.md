# Worker 执行权与迟到结果契约

2026-09-24，A07。实施与验收状态以 [实施进度](IMPLEMENTATION_PROGRESS.md) 为准；本契约不是部署或真实 PostgreSQL 验收证明。

## 原问题与保护范围

- 原 Worker 只在整个 handler 返回后检查心跳。九条初始隔离回归全部失败：策划后失权仍生成/审核；主 Session、独立进度 Session、批量 UPDATE、已 flush 后 commit 均可写入旧结果。
- 每次领取现在生成独立 `lease_token`，与 job/workspace/worker/attempt/running 状态和未过期租约一起校验。人工重试会重置 attempts，因此只有 Worker ID + 次数不够；同 Worker/同次数的新领取也不能复用旧执行权。令牌不是供应商幂等键，不替换原接受回执。
- SQLite 的领取采用候选状态/次数/旧令牌/原租约时刻条件更新，避免两个并发读者都声称领取成功；PostgreSQL 保留 `FOR UPDATE SKIP LOCKED` 并使用相同条件。未领取成功不会调用 handler。
- Heartbeat、完成和失败处理必须提供原令牌。续租先锁定原执行身份，再按锁等待后的时间检查过期；不能用一次迟到心跳重新续活已过期执行。

## 调用与业务写回

`ExecutionFence` 使用当前领取的不可变身份与心跳状态。独立读避免 ORM 缓存/旧事务快照；数据库无法验证时不继续调用，不把不可用当作允许。每个真实文本、Embedding、媒体生成/轮询、搜索、下载、平台 HTTP 请求前检查；下载跳转每一跳也检查。本地/S3 存储操作入口同样检查，本地临时文件落为正式对象前再检查。

Worker handler 的 ORM flush、commit、Session 执行的批量/原始 SQL 写入，以及独立进度 Session，共用执行上下文。条件 UPDATE 在**业务事务内**获取当前 Job 行锁，随后写业务数据；检查与写入不是两次无锁操作。提交前再核对，锁等待后再次检查租约时间。完成和失败传播也核对同一执行身份，不允许旧 Worker 把新状态改为失败或成功。

原始 SQL 默认保守检查；知识库的固定 pgvector SELECT 显式标注只读，防止一次查询意外持有 Job 写锁跨越模型调用。该约定是受信任应用代码的内部协议，不是任意 Python 插件的沙箱、数据库 RLS 或对恶意管理员的防护。

## 迟到证据不是新的业务执行权

- 调用账本 `start()` 受执行权门禁；证据 Session 与业务 Session 分开。`finish()` 在失权后仍可记录已返回调用的请求标识、响应 hash、用量，不保存模型原文或秘密。
- 确定返回但已失权的调用记为 `late_succeeded`，未知结果保留 `outcome_unknown`；保留已返回费用证据不等于把稿件/素材/发布状态自动认作成功。
- 文本、Embedding、媒体、搜索、下载返回后再次检查，不把迟到输出交给下一个业务步骤。公众号最后一跳即使返回成功，旧 Worker 也不能据此提交业务状态；已开始发布仍走既有超时/人工对账路径，不改为可安全自动重发。
- 失权时不由旧 Worker 擅自重排、清理、补发或改新状态。孤立对象、未完成运行及未知平台结果由后续有权的恢复/人工核对流程处理。

## 明确限制

素材还要校验内容版本、来源和操作身份；当前 A51/A52 候选的外部 I/O、charged staging、迟到结果回滚与人工回收协议见 [素材异步结果契约](asset_work_contract.md)。执行权保护不能替代素材版本保护。

- 校验不能撤回已经发出的远端请求。校验与网络发送之间不是跨系统原子事务；一次在途请求、S3 SDK 内部重试/分片仍可能结束，不能承诺供应商 exactly-once。
- 不在远端调用期间长期持有 Job 行锁来假装解决跨系统问题。业务事务仍应保持短小；新增锁顺序/热点需要 PostgreSQL 与容量验证，SQLite 绿色不能替代。
- A12 预算/并发、A47 可编辑成果检查点、A09 完整执行配置快照仍未完成。迟到调用的账本 hash 不是可恢复稿件，也不是零费用。

## 迁移与协调升级

执行权迁移 **e9f0a1b2c3d4** 紧接生成回执迁移 d8e9f0a1b2c3；仍至少 35 表，新增 `jobs.lease_token VARCHAR(32) NULL`。后续 A51 候选 head 已为 **f0a1b2c3d4e5**，新增暂存写入证据；不要再把 e9 当作当前最终 head。迁移保留历史任务，不给旧 running 任务伪造新领取令牌；新领取会写入新令牌。无版本库区分旧/新列，错误结构拒绝自动采用，恢复校验脚本同步 head。

部署必须先备份并停止/排空旧 Worker，处理原来在途和未知任务，迁移后协调 API/Worker/Web 版本，再启动新 Worker并验证恢复门禁。**不能混跑不检查令牌的旧 Worker**。真实降级必须停 Worker 并评估删除令牌/生成回执的去重损失，不能简单回退镜像。本轮只迁移隔离测试库，没有修改 Ubuntu 或真实数据库。
