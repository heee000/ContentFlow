# 媒体有效性与发布读取契约

2026-09-24，A39/A40。本地实现与验证记录见 [实施进度](IMPLEMENTATION_PROGRESS.md) 末节；本文件不表示已部署。

## 入库与读取

- 图片搜索下载、HTTP/Mock 生成、异步轮询和人工上传共用 `validate_media`。先完成大小、格式、解码检查，再分配对象/执行 PUT，失败不产生 ready 素材。原存储账本、配额、执行权和过期结果校验继续生效。
- 保存 `decoded-media-v1` 校验信息，尺寸和校验和来自实际字节。图片/分镜入库规范化后重新计算对象摘要，另存原始摘要。
- 发布预览的素材读取、API 分发、人工导出和脚本包使用 `ManifestObjectStorage`。先验证确认清单中的长度与摘要，再重新解码；不会信任旧 ready 状态或声称通过的 metadata。返回确认的原始字节，不在发布时重编码改变指纹。
- 人工上传的 CPU/子进程解码通过线程池运行。Worker 缺视频工具时在 HTTP 生成/轮询 Provider 调用前终止；已经生成后校验失败不会自动重发付费生成。排查原任务和失败素材后再采取明确操作。

## 支持边界

| 类型 | 接受条件 |
| --- | --- |
| image | PNG/JPEG/WebP，单帧，完整 Pillow 校验及加载；声明 MIME 必须匹配检测格式。搜索无可靠声明时允许从字节识别。按 `max_upload_bytes` 与 `publish_evidence_max_pixels` 限制，规范化重编码。 |
| video | MP4，声明 `video/mp4`，一个视频轨、至多一个音频轨，无额外轨道；正时长、不超过 300 秒、单帧不超过 3840×2160 像素、平均帧率大于 0 且不超过 60。 |
| video_storyboard | HTTP 视频结果可为上述 MP4；离线分镜是严格 UTF-8 JSON，顶层对象的 shots 必须是至多 200 个对象的数组。人工分镜上传仅接受 JSON；空 shots 可表达离线占位，不冒称成片。 |

视频检查包括有界顶层 MP4 box 长度、必需 ftyp/moov/mdat、ffprobe 元数据和 ffmpeg 完整音视频解码；解码必须正常结束并实际输出至少一帧。顶层 box 检查只验证封装边界，不声明完整 ISO BMFF 标准合规。[W3C 对 ISO BMFF 字节流的说明](https://www.w3.org/TR/mse-byte-stream-format-isobmff/) 是结构参考。

运行时 `ffmpeg`/`ffprobe` 必须在 API/Worker 的 PATH 内，Dockerfile 声明安装发行版包。探测最多 20 秒、解码最多 45 秒，使用固定临时文件路径、无 shell、限定 mov demuxer/本地协议并禁用外部 data reference；不把用户文件名/URL作为命令或输入路径。视频原始字节保持不变。容器构建和目标 Linux 版本的实际兼容性仍须部署验收，Windows 离线测试不能替代它。

## 审核、失败与旧数据

- 标题、正文、标签、CTA 和嵌套 layout 文本的审核及人工例外见 [内容审核契约](content_review_contract.md#31-a40-发布字段复查2026-09-24)。
- 独立分镜 JSON 的键和值中的文字按关联内容的冻结 Brief 禁用词检查，覆盖生成/上传/最终读取。它不是已批准正文的一部分，不能复用正文警告例外。
- 失败只输出固定错误码/处理指引，不保存解码器 stderr、临时路径或任意异常文本。无效文件、缺工具、超限、超时和分镜禁词都不可自动重试。人工上传 415，发布读取冲突停止分发；平台适配器仍按已有“是否已写入/结果未知”规则记录失败或要求人工核对。
- 旧 ready 对象不批量删除或重写；实际使用时重新检查。可重新选用有效素材或按现有替换/重建流程处理，并重新预览确认。解码失败不证明 Provider 未收费，不能据此清除未知结果证据。

本契约证明基本文件可解码与确定性文本规则，不证明画面/音轨语义合规、版权、营销质量、平台编码/尺寸要求或真实发布成功；没有 OCR/ASR。预算、Provider 并发、媒体解码总体容量仍属于 A12，真实 PostgreSQL/MinIO/镜像/平台验收另列。无 schema 迁移，现有 head 不变。
