# 模型输出契约 v1

实现：`contentflow/model_output.py`。适用于当前 Web 工作流的策划、成稿、审核与 Prompt Eval；不是供应商的 HTTP 请求格式，不更改模型/Prompt 内容，也不是事实正确性的证明。

## 边界

- 必须返回 JSON 对象。布尔值、字符串、列表、字典不相互强制转换；NaN/Infinity（包括扩展字段中的）拒绝。
- 审核必须包含真实 bool `passed`、low/medium/high 的 `risk_level`、0–10 有限数值 `quality_score`、九维 `scores`，以及 issues/fact_checks/strengths/revision_instructions 列表和 suggestion 字符串。零分保持零分，不使用其他维度的平均数替换。
- 策划要求受众问题、至少三个结构化角度、选择理由、论点/主张、证据条目、叙事结构、平台策略及未知事项；引用 ID 必须是字符串数组。此处只检查结构，引用是否真实属于当前检索上下文仍属 A10。
- 成稿要求字符串 title/body、标签数组和平台 layout。小红书校验封面/卡片，抖音校验镜头，公众号校验导语/段落/结尾；静音镜头允许空口播/字幕。正文长度质量、镜头数质量和事实仍由规则/质量评测负责，不能用结构校验冒充完整平台验收。
- 各字段有长度/条目上限，但解析前响应字节与 token/费用上限属于 A12，本次没有声称解决。
- 允许扩展字段以保存模型证据，但关键决策字段只能来自已校验字段。错误信息不回显原文、任意字段名或 Pydantic 原始输入。

## 收到响应不等于可使用

调用账本先记录响应已收到、哈希和供应商报告用量；应用随后做契约校验。结构不合格抛出 `ModelOutputError`，错误携带脱敏调用证据和独立 `output_validation` 失败信息。

不能因为坏输出就把已经返回的供应商调用改成“没执行”或抹掉费用，也不会为纠正格式自动增加一次模型请求。初稿/首次审核失败不能产出可审批内容；可选改写失败只允许保留此前已经完成审核的原稿，沿用既有有界回退策略。

## Eval 与上线

- 新 Eval 结果记录 `model_output_schema_version=1`；批准、激活与新工作流生成门禁只接受匹配当前契约的通过结果。
- 历史 Eval 保留原状，未标记契约版本的历史通过结果不作为新契约证据。升级会使这些工作区的新生成暂时不满足门禁；已存稿件不被删除或自动重生成。
- 部署前先完成 CI、保留镜像/数据回退点；部署后需另行限定真实评测范围与费用。没有复用既往一次性授权，也没有自动重跑 Ubuntu 的 r2。
- 后续契约出现不兼容变更时必须增加版本，补回归并重新取得对应证据；不能手工给旧 Eval 补版本来绕过验证。

## 回归

`tests/test_model_output.py` 覆盖严格类型、缺失字段、评分边界、三平台布局、证据结构与错误脱敏；`test_worker_v2.py` 验证字符串 false 不产生内容/素材且不自动重放；`test_prompt_eval.py` 验证旧契约评测不能放行、新契约通过后才能批准。
