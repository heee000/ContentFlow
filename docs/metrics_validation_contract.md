# 指标数值边界与历史异常隔离

对应审计 A42。修复的是异常数值写入后导致整个工作区指标接口持续 500 的路径，不等于完成 A33 的统计口径整改。

## 写入边界

- API 与采集 Worker 共用 `MetricValues`：五个计数必须为有限 JSON 数字，范围为 0 至 9,007,199,254,740,991。拒绝数字字符串、bool、负数、NaN/Infinity 和超上限值。为兼容旧接口，有限小数暂仍接受；整数与平台计数语义待 A33 统一。
- 人工接口也拒绝 `raw` 嵌套 NaN/Infinity，未知字段拒绝，不允许客户端设置隔离状态。校验错误只返回安全字段位置，不回显输入。
- Worker 不再用 `float()` 宽松转换供应商值；非法返回在快照入库前失败。此处是读取指标，不涉及平台发布或生成费用重试。
- 数据库新增两项 CHECK：状态仅为 valid/quarantined；正常记录五项均在边界内。PostgreSQL 的 NaN 比较与 SQLite 不同，分别设置回归测试，不能以 SQLite 结果代替 PG 验收。

## 历史数据与页面

- 迁移 `c7d8e9f0a1b2`（前置 `b6c7d8e9f0a1`）只给已有越界记录标记 `quarantined`，不删除、不截断、不替换为零，原时间、原值和 raw 均保留。状态可作后续人工修复的筛选依据，不是已完成核对的声明。
- 汇总同时检查状态和真实数值边界，按当前工作区/项目统计 `excluded_snapshot_count`；存在异常则 `data_complete=false`、不生成建议。异常条数不能泄漏到其他工作区或无关项目。
- 页面明确显示“不完整、已排除异常、原值保留”；只展示有效记录汇总。指标接口暂不可用时单独显示错误和重载入口，不显示假的零值，也不阻断其他数据队列。401/403 仍走原身份失效逻辑。
- 暂无面向普通用户的隔离记录修复界面。管理员后续应对照平台原始记录核对，保留修复审计，不应直接删除异常来消除提示。

## 升级与回退

- 与审核证据迁移一起协调升级 API/Web/Worker；当前 head 为 `c7d8e9f0a1b2`，表数量仍至少 34。旧服务不识别隔离状态，混跑会重新暴露旧汇总行为，不能视为升级完成。
- 升级前备份并统计异常；大表 UPDATE/SQLite batch 重建可能持锁，生产规模迁移耗时尚未验收。不能套用合成小数据库的耗时。
- downgrade 保留指标原值但移除标记/约束，会重新暴露旧风险；只在可丢弃测试库做了自动回退演练，真实回退必须先备份隔离证据并制定兼容计划。
- 未部署到 Ubuntu，未迁移真实业务库。

## 未解决的统计问题

A33 仍开放：累计快照重复求和、快照数不等于作品数、取消/草稿等状态是否允许录入、统计窗口和平台定义差异。字段缺失当前仍沿用零默认值；不能据此宣称真实业务指标完整或足以做商业归因。前端其他接口的批量失败耦合属于 A16，当前仅隔离指标故障。
