# 平台连接器与权限边界

## 共同规则

所有平台发布都要求：

1. 内容与连接器属于同一工作区
2. 内容平台和连接器平台一致
3. 内容为人工审核通过状态
4. 排期记录保存的内容版本仍是当前版本
5. 所有素材已生成完成
6. 幂等键未被使用

官方 API 凭据由后端加密保存，API 和前端不会回显。脚本辅助和人工导出连接拒绝接收平台凭据。

## 抖音

实现节点：

- OAuth 用户信息测试
- 视频文件上传
- 使用 `video_id` 创建作品
- 按 `item_id` 回收播放、点赞、评论和分享数据

需要非空 `access_token`、`open_id`，并要求开放平台应用已获得相应 scope。创建渠道时 API 会同步校验这两个运行时必需字段，`open_id` 可放在加密凭据或非敏感配置中。即使接口地址正确，未审核应用、未授权用户或受限内容仍会被平台拒绝。参考[抖音开放平台内容发布解决方案](https://open.douyin.com/platform/resource/docs/ability/content-management/douyin-publish-solution)。

## 公众号

实现节点：

- 使用 App ID/Secret 获取 access token
- 上传封面到永久素材
- 创建草稿
- `auto_publish=true` 时提交发布
- 以返回的 `publish_id` 查询发布状态；没有 `article_id` 时保持 pending，取得后才标记 published

默认配置只创建草稿，避免未经运营人员确认直接群发。自动对账使用确定查询键并允许 reviewer 人工接管，不会根据含糊状态猜测成功。不同公众号类型和认证状态拥有不同接口权限，必须以目标账号的实际权限集验收。

## 小红书

系统没有把未确认的公开发布接口包装成“自动发布”。连接器执行：

1. 确认内容已审核
2. 收集标题、正文、标签、CTA
3. 写入 `manifest.json`，包含内容 ID、版本和人工审核状态
4. 收集已生成素材
5. 输出带鉴权下载的 ZIP 投放包

运营人员在小红书后台人工发布后，可通过指标录入接口补充数据。

## 本机脚本辅助

管理员可为小红书、抖音或公众号创建 `script` 连接；reviewer 也可在创建发布任务时直接选择脚本辅助，或在确认尚未产生平台副作用的失败任务上改用脚本。系统会生成确定性 ZIP，包含审核版本、素材、`manifest.json`、`SHA256SUMS`、固定版本 `requirements.txt` 和 `publish_assistant.py`。

运行器在本机使用 Playwright 持久浏览器目录 `~/.contentflow/browser-profiles/<platform>/<channel_id>`：

1. 校验任务包每个文件的 SHA-256、路径和重复条目；
2. 只接受内置平台与官方入口，不信任任务包自带的任意登录 URL；
3. 要求用户在官方页面人工登录并进入编辑页；
4. 尽力上传素材和填充标题/正文；页面变化时退化为人工复制；
5. 不查找、不点击最终发布/提交按钮；用户核对账号、声明、可见范围和时间后自行决定；
6. 回到 ContentFlow 登记 `script_published` 或“未发布”，后者可重新生成任务包；自动指标拉取仅允许官方 API 任务，脚本任务使用人工指标录入。

若官方 API 已开始调用而结果不确定，任务进入 `reconciliation_required`，系统禁止直接切脚本。只有平台人工确认未发布后进入 `failed`，才能显式切换。这是防重复发布门禁，不是故障。

## 真实账号验收清单

- 使用测试应用/账号，不要直接以正式品牌账号做首次联调
- 记录应用 scope、回调地址、用户授权时间和 token 过期时间
- 分别测试连接、素材格式错误、平台限流、审核拒绝和成功路径
- 区分平台接收 ID 与最终内容 ID/URL；只有平台实际返回最终标识后才保存为已发布
- 对同一排期重复执行，验证不会创建重复作品
- 撤销授权后确认连接测试进入 `invalid`
